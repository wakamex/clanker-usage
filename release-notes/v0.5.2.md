This release makes failed readings visible to other tools and records Claude's response for accounts without a 5-hour limit.

- Every command now records failed fetches the same way. The `daemon` command used to write its failures only to its log, and a successful fetch left an earlier command's failure on record. Now each failure is counted in `~/.local/state/clanker-usage/backoff/PROVIDER/ACCOUNT.json`, and the next successful fetch removes that file. A tool watching that directory sees every failure and every recovery, and `statusline` stops retrying during an outage the daemon found ([`62248a9`](https://github.com/wakamex/clanker-usage/commit/62248a9e5e7de212be79cc90efd89a63acba90e5)).
- Claude Code: Anthropic renamed Max 20x to Ultra, and [verified Ultra accounts have no five-hour limit](https://support.claude.com/en/articles/17728952-what-is-the-ultra-plan). Their usage response lists only the weekly limits, so their readings have no `5-hour` window, and the plan still reads `max_20x`. The response also adds `extra_usage.credits_can_pay`, a string such as `"no"`. `check` now accepts this shape instead of reporting a new one ([`3bebc4c`](https://github.com/wakamex/clanker-usage/commit/3bebc4c9b3a63fd8b0788dc0f4578ec39d857dab)).
