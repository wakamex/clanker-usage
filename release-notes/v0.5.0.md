This release adds a Python API for programs that read usage, such as a scheduler deciding whether to start an agent, and fixes readings for used-up windows.

- `clanker_usage.read(provider, account)` returns an account's cached usage-v1 document, or `None` when there is none; `documents(provider)` returns every cached account; `account(provider, home)` returns the account a Claude Code, Codex or agy credential home is signed into, from local files only, and raises `AccountUnknown` when it cannot tell. The README's "What stays stable" section lists what keeps its meaning from 0.5.0 while the schema is usage-v1 ([`6773478`](https://github.com/wakamex/clanker-usage/commit/677347840686d96d4eb0670a60930cb0386c8c9c)).
- Devin: a used-up window no longer disappears. Devin leaves out a remaining share of zero, so a full week showed only the daily window; it now reads 100% ([`456572f`](https://github.com/wakamex/clanker-usage/commit/456572ffc1defdbd35ffefea4b8a1ed410845d60)).
- Muse Code: a used-up window, which Muse reports as 101%, reads 100% with the reported value kept in `details.reported_used_percent`, instead of being rejected ([`a2a94a7`](https://github.com/wakamex/clanker-usage/commit/a2a94a7e49af12b9baf345848f0cffab39b67e49)).
- Antigravity and Gemini CLI: the plan includes the tier id, such as `Google AI Ultra (g1-ultra-lite-tier)`, since Google's $100 and $200 Ultra tiers share a name ([`6af69cb`](https://github.com/wakamex/clanker-usage/commit/6af69cbcc3734719c318c4e92f7e8160e3c6abc2)). Scripts that matched the plain plan name need the new form.

The two Muse commits that marked a missing usage field as expected were reverted within this release; a response without usage is a failed fetch, as before, now with a clearer message ([`b4c43ec`](https://github.com/wakamex/clanker-usage/commit/b4c43ec6f3940e9c5cf575c45e09961c374558fe)).
