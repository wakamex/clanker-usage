This release keeps Muse Code's reading current when Meta's server leaves usage out of its response.

- Muse Code: Meta sends no usage while no 5-hour window is open, that is, until Muse is used again after a window resets. Muse 1.4.23 was checked through a whole window on 2026-11-17: usage was missing before the first use, present in every call while the window was open, and missing again after it reset. Once the last reading's window has reset, such a response now reads as the 5-hour window at 0% and the weekly limit at its last reading, or 0% after its own reset, with `details.source` set to `no open window` and `details.carried_from` giving when the carried values were measured. While the last known window is still open, missing usage is still a failed fetch ([`c67e339`](https://github.com/wakamex/clanker-usage/commit/c67e3394104af6864561db437a6843625fcc97b8)).
- Muse Code: a gap can also be filled from Muse runs another tool recorded. `muse exec --json` ends with the usage as of its last model call, and aop keeps that output; add its location once with `muse-code-usage configure --run-glob '~/work/*/.aop/runs/*/events.jsonl'`. A recorded reading never replaces a newer one ([`1d29cae`](https://github.com/wakamex/clanker-usage/commit/1d29caef0ffda4bab17e469157dbd387048e8f57)).
