This release keeps `deepseek-harness-usage` working with DeepSeek Harness 0.2, and explains why `gemini-cli-usage` finds no quota for most Gemini CLI users.

- DeepSeek Harness 0.2 rewrites its credential store into a new layout, which 0.4.0 rejected with "The value for version in ~/.dsh/.credentials.yaml is not a string". The balance now reads again with either layout. With Harness 0.2, the stored key also takes precedence over an exported `DEEPSEEK_API_KEY`, as it does in Harness itself, and the custom-endpoint check also covers routes set in Harness's profile patches ([`ec830dd`](https://github.com/wakamex/clanker-usage/commit/ec830ddf71e05a02eec61a033efdc2220ec79a83)).
- Google ended Login with Google in Gemini CLI for individual, Google AI Pro and Ultra accounts on 2026-06-18; only Gemini Code Assist Standard and Enterprise keep it. For any other login, `gemini-cli-usage` now says so and points to `agy-usage`, which reports that quota through Antigravity ([`3dbc189`](https://github.com/wakamex/clanker-usage/commit/3dbc1898d21ffc70c23df6a2a1ee0f367bb05d44)).

## Changes
