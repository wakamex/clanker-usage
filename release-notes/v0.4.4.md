Run as a systemd user service, `devin-cli-usage daemon` failed every request with "Usage request failed (HTTP 500)". A user service's `PATH` leaves out `~/.local/bin`, where Devin installs itself, so the tool could not find the `devin` command, sent its version as `unknown`, and Devin's server rejected that. The same request from a shell succeeded. Every provider now also looks in `~/.local/bin`, `~/bin`, `/usr/local/bin` and `/usr/bin` for a harness's command, which also fixes token renewal for Gemini CLI and Antigravity under a service, and Devin sends a real version when its command is missing ([`7f14cf0`](https://github.com/wakamex/clanker-usage/commit/7f14cf01974fb5be41120a352aff72020f9ab980)).
